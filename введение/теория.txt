API 
HTTP (get, post, put, patch, delete)
HTTP-коды состояний 1хх, 2хх, 3хх, 4хх, 5хх
REST-архитектурный стиль при передаче данных.(список ограничений)
1)Клиент-сервер - разделение ответственности
2)Stateless(отсутствие состояния)-сервер не хранит
состояние клиента между запросами
3)Кэшируемость-ответы должны явно помечаться как кэш.
или нет
4)Единообразие интерфейса-одинаковые правила для 
взаимодействия
5)Слоистая система - клиент не знает, общается ли он
с конечным сервером или с промежуточным прокси
6)Код по требованию(опционально)-сервер может передавать
исполняемый код клиенту

Единообразие интерфейса:
1)Идентификация ресурсов через URL: 
/getBooks?id=1     /books/1
2)Манипуляция ресурсами через представление (JSON/XML)
3)Самодостаточные сообщения (в запросе вся необходимая инф)
4)HATEOAS - гипермедиа как двигатель состояния приложения
(в ответе есть ссылки на следующее действие)
